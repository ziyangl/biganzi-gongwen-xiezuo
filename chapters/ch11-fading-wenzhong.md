# Chapter 11: 法定文种——15种公文与高频文种套写

## Core Idea
15种法定公文（决议、决定、命令、公报、公告、通告、通知、通报、议案、报告、请示、批复、意见、函、会议纪要）各有法定框架："如果你的行文框架错了，那么内容也就不可能符合要求"。

## Frameworks Introduced
- **15法定文种地图**（《党政机关公文处理工作条例》规定）：
  - 下行指挥类：决定、命令、通报（表彰/批评）、批复、通告
  - 周知类：公告、公报、通知、会议纪要
  - 上行类：报告（汇报工作/反映情况/答复询问，不夹带请示事项）、请示（一文一事、主送一个上级机关）
  - 平行类：函（商洽工作、询问答复；分征求意见函、修改意见复函、邀请函等）
  - 议事类：意见、议案、决议
- **高频文种共性模板结构**（朱立东、李永新，每文种给"共性模板+常见套件+高频词句"）：
  - 会议通知：缘由 → 会议时间 → 会议地点/方式 → 参会人员 → 有关事项 → 联系方式
  - 请示：缘由（根据……整体安排）→ 事项（分条列明：标题/时间/地点/方案）→ 结语（妥否，请批示）
  - 批复：引语（你单位《关于……》收悉）→ 意见（同意/原则同意/不同意+理由）→ 要求
  - 报告：工作情况（举措+成效）→ 存在问题 → 下步打算
  - 会议纪要：会议概况（时间地点主持人议题）→ 议定事项（分条）→ 工作要求
- **硬规矩**（条例要点）：请示一文一事；报告不得夹带请示；请示主送一个上级机关；联合行文需同级

## Key Concepts
- **法定公文 vs 广义公文**：狭义即15种；广义还包括计划总结、讲话类、章程条例等实物类/讲话类/规范类文书（陈征）
- **文种选择错误是"0.9版"问题**：本该用请示却用报告，格式再好也不合格
- **体例先行**：先对文种框架，再填内容；不常写的文种先找经典范例琢磨体例

## Mental Models
- 法定文种是"制服"：款式颜色标识统一，不能擅自改设计、不能混搭
- 模板三层：骨架（不能错）、套件（按场合选）、词句（按口味换）

## Anti-patterns
- **文种混搭**：用批复口吻写请示、把对上汇报写成对下讲话
- **自造文种**：公文里没有"情况反馈"这个文种
- **报告夹请示**：违反行文规则，上级无法定程序答复

## Worked Example
会议类请示套写（按笔杆子2模板1骨架）：标题《××局关于召开全市××工作会议的请示》；正文——"根据××整体安排，拟于×月×日召开全市××工作会议，专题研究××，拟请××领导出席会议并讲话。现就有关事项请示如下：一、会议标题：建议为'全市××工作会议'。二、会议时间：×月×日（星期×）×时，具体时间根据××同志工作安排确定。三、会议地点：××。四、参会人员：××。五、会议方案（附后）。妥否，请批示。"注意三处法定细节：主送只写一个上级机关；一文一事（只请示开会这一件事）；结语用请示专用语。套改路径：翻出本单位最近一次获批的同类请示，改参数留骨架。

## Key Takeaways
1. 动笔先答：这是什么文种、对谁行文、上行下行平行
2. 请示三铁律：一文一事、主送一个上级、结语"妥否，请批示"
3. 框架错则全错：先比对条例与近期获批定稿，再动笔
4. 每个文种存一份"最近获批的定稿"作体例基准
